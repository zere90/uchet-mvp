## Этап 2. Движок проведения и регистры ✅

- [x] Загрузка правил из `meta_posting_rule`, вычисление условий `when`
- [x] Формирование движений `reg_stock`, `reg_settlement`, `reg_price`
- [x] Формирование проводок `acc_entry`
- [x] Проведение в одной транзакции с блокировкой документа (FR-05)
- [x] Повторное проведение не удваивает движения (FR-06)
- [x] Контроль «дебет = кредит = сумма документа» (FR-09)
- [x] Отмена проведения (FR-07)
- [x] Ошибка «правило не подошло ни к одной строке»

Проведение и отмена реализованы в `app/posting.py`; API этапа 3 использует этот движок.
Ошибки проведения возвращаются в общем формате HTTP 422 (`posting_failed`).
Суммы проверяются с `Decimal`, округление строк — до двух знаков, половины вверх.
Строка с нулевой ценой требует правила, но не создаёт нулевую проводку
(ограничение `acc_entry.amount > 0`); движения регистров сохраняются.
Внутри внешней транзакции движок использует точку сохранения; окончательное
подтверждение внешней транзакции остаётся за вызывающим кодом.
Проверены блокировка, откат при ошибках, аудит и изменение правил без изменения кода.
